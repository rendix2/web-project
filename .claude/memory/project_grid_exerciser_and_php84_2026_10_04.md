**GridExerciserCest** (`tests/Functional/`, same file shape in alfred / family-tree / web-project) walks EVERY datagrid of the admin over real HTTP: every sort link (asc+desc reorder only), every filter (text junk value must give 0 rows, select/multiselect options, date incl. junk "not a date", range from/to incl. junk), hide/show every column, perPage choices, reset via `data-datagrid-reset-filter-by-column`. `_after` fails when `log/**/exception.log`, `error.log` or a new `exception--*.html` grew (the datagrid swallows its own errors: page = 200 without the grid). All markup knowledge is in `tests/Support/Grid/DatagridPage.php` (understands ublaboo 6 `datagrid-<name>` AND contributte 7 `data-datagrid-name`; identical file in the 3 projects) -> the datagrid/Bootstrap 5 update changes only that adapter. Results: alfred 14/14, web-project 4/4, family-tree 89 pages (last run being finished, see below).

**Bugs it found (all fixed):**
- PostgreSQL leftovers: `REGEXP(...) = 1`/`eq(.., true)` vs boolean (`integer = boolean` / `boolean = integer`) - web-project UserDataGrid, family-tree (101 lines; its `PostgresqlRegexp` now returns a real boolean like alfred/web-project, ALWAYS compare `= true` / `eq(..., 'true')`); alfred `COLLATE(...)` (MySQL collation in sort callbacks -> new DQL `Collate` function, pass-through on PG) and `DATE()` (registered `DoctrineExtensions\Query\Postgresql\Date`, also `Hour`).
- Parameter-name collision (the "member" bug): a grid embedded on a detail page binds `:member` (entity) in its base query and the filter condition of the SAME grid binds `:member` again with the typed text -> `invalid input syntax for type bigint` (alfred MemberAiTokenUsage/MemberChat/MemberNick/MemberPublic grids; family-tree 6 grids on edit pages). Fix: base-query parameters are named `ownerX` (alfred) / `baseX` (family-tree, renamed mechanically in 51 `app/controls/Grids/*Grid.php`). Rule: never reuse a filter's parameter name in a base query.
- alfred: AiTokenUsageGridFactory `id` filter condition was a copy of a sort callback; date filters passed `false` to SQL on junk input (`1 = 0` now); EventGrid parent filter DQL typo `'(:eventParents'`; KarmaGridFactory `'(_toMember.firstName'` typos; HistoryNoteGrid (family-tree) missing sort/condition for `personGender`.
- alfred `DatabaseLogger` lost every exception whose trace had an enum/closure argument (json_encode) -> trace stored without args.
